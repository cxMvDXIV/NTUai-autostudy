# 南通大学 AIGC 课程平台刷课脚本

在浏览器里一集一集点视频太磨人，这个工具替你把这个活干完：进度走平台自己的上报接口，刷完直接在屏幕上告诉你刷了几门课、几节、新增多少时长、进度从多少到多少。账号密码不写死在代码里，同学拿去填自己的就行。

**怎么用**：把整个文件夹拷到电脑上，或者在 GitHub 上点 `Code` -> `Download ZIP` 再解压。装了 Python 就双击 `刷课.bat`，没装 Python 就双击 `刷课.html`。嫌整个文件夹大，只把 `刷课.html` 一个文件拷走也能刷，它只要浏览器。

**适用**：南通大学 AIGC 课程平台（`xdplus.com.cn`）。不是通用刷课工具，换个平台接口名就不对。系统要 Windows（bat 和路径都是 Windows 写法），`刷课.html` 在 Chrome 或 Edge 里都能打开。

**先知道**：这个平台没有学习通那种刷课监控，接口模式不会被自动挑出来，但"一天刷完 30 多小时"在服务端是留痕的、删不掉，给谁用都自己掂量；脚本只管视频课时，考试、作业、缴费、证书申请都不管。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `shua.py` | 主程序，只用 Python 自带库，接口模式不需要装任何东西 |
| `刷课.html` | 不用装 Python 时的首选：双击就在 Chrome 里打开，输账号密码、勾课程、点开始，进度和汇总直接显示在页面上 |
| `刷课-浏览器.js` | 不想装 Python 时的替代：在已登录的网页控制台里粘贴运行，效果等同接口模式 |
| `刷课.bat` | 双击运行，走引导流程（接口模式） |
| `刷课-播放模式.bat` | 双击运行，直接进播放模式，照样会问选修 / 倍速 / 课程（首次自动装 playwright） |
| `刷课状态.json` | 保存登录 token 和账号密码，下次进来直接回车沿用；删掉或跑 `py shua.py forget` 就是换人 |
| `.chrome-play/` | 播放模式的浏览器配置目录，只有播放模式才用 |

## 两种模式

| 模式 | 原理 | 16 节必修（12 小时 49 分）耗时 |
| --- | --- | --- |
| `api`（默认） | 直接调用平台自己的 `submitStudyDuration` 接口，把每节时长分几次递增上报 | 实测约 1 分钟 |
| `play` | 打开 Chrome 播放视频，倍速连播，进度由页面自己上报 | 3 倍速约 4.3 小时 |

接口模式上报的时长不会超过每节的要求时长，平台自己会截断，所以刷不出超额数据。播放模式更接近真人观看，代价是时间长、要留一个 Chrome 窗口在前台。

## 常用命令

不带参数就是引导流程，命令行传过的项就不再问：

```powershell
py shua.py                             # 引导流程：问账号密码、模式、选修、课程
py shua.py run --elective              # 不问，接口模式，连选修一起刷
py shua.py run --no-elective           # 不问，只刷必修
py shua.py run --mode play --speed 2   # 播放模式，2 倍速
py shua.py run --course all            # 账号下所有课程都刷
py shua.py run --course 21,20          # 只刷这两门
py shua.py run --stop-at 50            # 课程进度到 50% 就停
py shua.py run --limit 3               # 每门课本次最多刷 3 节
py shua.py status --all                # 看当前进度和每节完成情况（含选修）
py shua.py courses                     # 列出账号下的课程
py shua.py forget                      # 清掉保存的登录态，换人用
```

主要选项：

- `--account` / `--password` 换账号；不传就在屏幕上问，密码输入不回显
- `--mode api|play` 不传就在屏幕上问
- `--elective` / `--no-elective` 命令行模式下不传默认只刷必修，引导流程里默认连选修一起刷（会问你）
- `--course` 课程 id，逗号隔开或者 `all`；不传就在屏幕上列出来让你挑序号
- `--speed` 播放模式倍速，平台最高支持 3
- `--steps` / `--gap` 接口模式每节分几次上报、每次间隔几秒，默认 6 次 / 2 秒
- `--stop-at` 进度百分比到了就停
- `--no-mute` 播放模式保留声音，`--headless` 不显示窗口
- `--period-timeout` 播放模式单节最长等待分钟数

## 刷完会汇总什么

刷完直接在屏幕上给一段结果，不用自己去页面对：

```text
================================================
  本次刷课结果
================================================
【AIGC入门】提示词工坊与AIGC基础应用
  刷了 16 节，新增 12小时49分，用时 1.0 分钟
  完成节数 0/48 -> 16/48，已学 0小时00分 -> 12小时49分（这门课要求 36小时21分）
  平台显示进度 0% -> 33.33%
------------------------------------------------
合计：刷了 1 门课，16 节，新增 12小时49分，总用时 1.0 分钟
      本次共处理 1 门课，其中 0 门课时已全部刷满
```

`已学` 和 `要求` 都按每节的要求时长封顶，所以这两个数字不会被平台里那些重复记录灌水。平台自己显示的"整体进度"偶尔会超过 100%，原因见最后两节。

## 几个要知道的点

1. 这个平台只保留最后一次登录。脚本登录会把浏览器里的登录态顶掉，反过来也一样。脚本发现 token 失效会自己重新登录，不用管；你在网页上如果提示登录失效，重新登录一次就好。
2. 登录成功后账号和密码会明文存在 `刷课状态.json` 里，省得每次都输。这台电脑给别人用、或者要换账号，跑一次 `py shua.py forget`（或者直接删这个文件）。密码文件里存的是明文，跟那个 token 一样敏感，别把整个文件夹随便发给别人时忘了这一点。
3. 播放模式默认静音，Chrome 会节流后台页面，所以别把那个 Chrome 窗口最小化。想彻底不占地方就用 `--headless`。
4. 脚本只刷视频课时，班级考试、作业、证书申请这些不管。
5. 这个平台没有学习通那种"AI/大数据监控刷课"，接口模式本身不会被自动检测出来，实测依据见下面三节。真正容易被看出来的是"一天刷完 36 小时"这件事本身，跟用哪种模式无关；服务端只存每个课时的最后学习时间，所以以后用 `--limit` / `--stop-at` 分几天刷，记录看起来就跟真人一样。
6. 中途想停就按 `Ctrl+C`，已经刷进去的进度不会丢。

## 换台电脑跑不起来

最稳的做法是把整个文件夹拷过去。只想带最少的文件：装了 Python 的电脑带 `shua.py` + `刷课.bat`，没装 Python 的电脑只带 `刷课.html` 一个文件就行，双击就能刷。`刷课状态.json` 可带可不带：带着就不用重输账号密码，代价是那台电脑上也会留一份明文密码；不带的话第一次会让你输。`刷课.html` 的登录态存在浏览器里，跟这个文件夹无关，拷到哪里都要重新登录一次。

按现象对号入座：

- `can't open file 'C:\Windows\shua.py'`（或者别的盘符下的 `shua.py`）：这条报错是 `python.exe` 自己打出来的，说明那台电脑其实**有** Python，只是 bat 当时的工作目录跑偏到 `C:\Windows` 去了，于是按相对路径去找脚本没找到。老版本就是这么挂的。现在 bat 先按自己所在目录定位脚本、再用绝对路径调起来，`cd` 失败也不会跑偏。要是整个文件夹就没拷全，它会直接打 `[ERROR] shua.py not found next to this .bat` 加它期望的完整路径，照那个路径把 `shua.py` 和 bat 摆到同一个文件夹再双击。
- `can't find '__main__' module in '...'`：同样是那个文件夹里没有 `shua.py`。
- 双击后窗口一闪就没：说明脚本压根没跑起来，多半就是上面两条；正常跑完会停在 `Press any key`。
- `Python is missing or not usable on this computer`：那台电脑没装 Python，或者装了但没进 PATH。bat 现在会自己查出来、打这句话，并且顺手把这个文件夹里的 `刷课.html` 打开，不想装 Python 就直接在网页里刷。要装的话去 Microsoft Store 搜 Python，或者从 https://www.python.org/downloads/ 下安装包，装的时候勾上 `Add python.exe to PATH`，装完关掉那个黑窗口再双击一次。
- 双击后只打了一句 `Press any key to continue . . .`，前面什么都没有：老 bat 就是这么哑掉的，有两种常见走法。一种是 bat 用管道去探测 Python（`python ... | findstr ...`），命令本身不存在时 cmd 会直接中止整个 bat，错误又被 `2>nul` 吞掉，`pause` 之后的话一句都不打——这条我在这台电脑上把 PATH 砍成只剩 `C:\Windows\System32` 复现过，退出码 255。另一种是 Windows 自带的那个 `python` 空壳（在 `WindowsApps` 里，点了会跳 Microsoft Store），它既不报错也不真跑 Python，bat 就一路走到 `pause`。现在的 bat 两样都绕开了：探测结果写进临时文件再查，不走管道；认的是"真的把 `20261025` 打出来"才算 Python 可用，那个空壳过不了这一关。而且它一上来就先打 `folder:` 和 `python:` 两行，所以要么这两行加正常输出，要么一句明确的 `[ERROR]`，不会再什么都不打。
- `'python' 不是内部或外部命令` / `'py' 不是内部或外部命令`：也是没装或者没进 PATH，同上。
- 中文乱码：bat 里已经带了 `chcp 65001`。还乱码就先在 cmd 窗口里敲 `chcp 65001` 回车，再双击 bat。
- 提示 `play 模式需要 playwright`：只有播放模式要装，双击 `刷课-播放模式.bat` 首次会自动装，或者自己跑 `py -m pip install playwright`。接口模式什么都不用装。
- 没有 `py` 命令：bat 会自动退回用 `python`；自己敲命令的话把 `py` 换成 `python` 就行。

那台电脑装不了 Python（比如学校机房不让装软件），下面这一节的两个东西都不用装 Python。

## 不想装 Python

### 首选：双击 `刷课.html`

[刷课.html](刷课.html) 双击就在 Chrome 里打开，跟用脚本一模一样地刷，只是不用装任何东西：

1. 双击 `刷课.html`（它会用这个文件所在的文件夹，不用拷到别处）
2. 输账号和密码，点登录
3. 勾上要刷的课程，要不要连选修一起刷、每节分几次上报、间隔几秒、每门课最多刷几节、进度到百分之几停，都在页面上填
4. 点开始刷课，进度一行一行打在下面的输出区，刷完打同一段汇总；中途想停点停止

账号密码和登录态存在这个页面自己的存储里，下次双击自动沿用，省得重输；换人点换账号。它登录用的是这个页面自己的身份，会把课程平台网页端的登录顶掉（平台只保留最后一次登录），网页端提示重新登录是正常的。只有接口模式，没有播放模式。

### 不想顶掉网页登录：`刷课-浏览器.js`

[刷课-浏览器.js](刷课-浏览器.js) 走的是另一条路——直接用你浏览器里已经登录好的身份，不会把网页端的登录顶掉：

1. 用 Chrome 打开课程平台并登录，进到任意一门课的页面
2. 按 `F12`，切到 Console（控制台）
3. 把 `刷课-浏览器.js` 的全部内容粘进去，回车

要调的东西都在文件开头的 `CONFIG` 里：`elective` 要不要连选修、`courseIds` 刷哪几门（空数组是全刷）、`steps` / `gapMs` 每节分几次上报和间隔毫秒、`limit` 每门课最多刷几节、`stopAt` 进度到多少就停。改完再粘一次。

两个都只有接口模式；播放模式必须用 Python 那套。

## 平台监控实测

前端能做的防刷，这个平台只做了很浅的一层，而且全在浏览器里：

- 切到后台标签页会自动暂停（`visibilitychange`），拖到已看位置之前会被拉回，倍速只给 0.5 到 3 倍，课时按顺序解锁（点未解锁的课时提示"请按顺序完成课时学习"）
- 没有摄像头和人脸识别、没有鼠标键盘记录、考试页没有切屏计数、没有 `sendBeacon`，整个前端只有 `visibilitychange` 这一个行为监听

  这条结论是把入口 HTML 和全部 36 个前端 JS 分包逐个扫过得出的（入口引用的 36 个分包全部抓下来了，没有漏掉的）：`sendBeacon`、`WebSocket`、`getUserMedia`/摄像头、指纹采集、鼠标键盘监听全部为 0 次命中；`PersonalCenterView` 里的 `face`/`canvas` 全部来自头像裁剪库，`ExamTakeView` 里的 `beforeunload`/`pagehide` 只是把答案存进 `localStorage` 防丢，考试页没有任何监考逻辑。整个前端一共 48 个接口名，登录、支付、发票、证书、考试、公告都在里面，但跟观看时长有关的写入只有 `submitStudyDuration` 一个；其余的写接口只有考试交卷 `OnlineAnswer`、证书申请 `applyCertificate`、公告标已读 `markNoticeRead`，都不记观看时长。

上报接口 `submitStudyDuration` 只发 7 个字段：`user_id`、`course_id`、`chapter_id`、`period_id`、`class_id`、`study_duration`、`period_type`。没有播放速率、没有会话 ID、没有设备指纹，脚本发的和网页发的一字不差。服务端校验是：用户身份必须跟 token 一致（否则 403 用户身份不匹配）、课时必须存在、章节要跟课时匹配、课程必须存在、时长必须大于 0；时长按分钟取整加一，并截断在课时要求时长内。

服务端存储是每个课时一行可覆盖的记录，字段只有分钟数和最后学习时间，没有心跳历史。实测两次上报只隔 2 秒也照样接受，说明不校验上报节奏。有一点要注意：服务端是按"课时 + `period_type`"分行存的，同一个课时用两个不同的 `period_type` 上报就会留下两行，而课程页读的是最后写进去的那一行，不是取最大值。脚本上报时照抄平台自己给的 `period_type`（选修课时是 1、必修是 0），所以不会凭空造出重复行。平台自己的"学习数据"页只是把 `studyStatistics` 的四个数字显示出来，图表数据和"+0%"都是前端写死的示例，背后没有真的行为分析。统计用的是 51.la 通用网站访问统计，记的是访问不是观看。公告接口 `noticeList` 返回空，站内没有任何防刷课声明。

网页自己也是每 2 秒上报一次（分包里心跳间隔常量是 2000 毫秒），而且要求画面可见、播放位置真的往前走了才发。脚本默认 6 次 / 2 秒的节奏跟网页一模一样，区别只在总耗时。

## 一天刷完 30 多小时，风险到底在哪

自动检测层面：没有风险。服务端没有每日学时上限、没有"有效学习"标记、没有异常字段、没有回滚机制。证据是它连自己算出来的 109% 进度和班级字段错乱的重复记录都照收不误，`is_completed` 也已经变成 true、考试报名早就解锁了。

人工查看层面：风险在这里，而且跟用哪种模式无关。服务端每个课时留一行"分钟数 + 最后学习时间（精确到秒）"，当前账号的真实状况是：

- 48 个课时的首次写入全部落在 2026-10-25 这一天，只集中在 11 个不同的分钟里：16 节必修写在 00:41 和 00:57~00:58 这两分钟里，相邻课时隔 3~5 秒；32 节选修写在 10:54~11:01 这七分钟里，相邻课时隔 13~15 秒
- 总学时 2349 分钟（39 小时 09 分），整门课要求 2181 分钟（36 小时 21 分，其中必修 769 分钟 = 12 小时 49 分）
- `continuous_study_days` = 1

也就是说，谁打开后台看你的学习记录，都会看到"36 个小时的视频在十几分钟内学完"。这个痕迹删不掉，只能靠以后跨天刷来稀释。

顺带一个平台自己的显示 bug：`studyStatistics` 返回的 `total_study_duration_text` 是 `"00:39:09"`，服务端把分钟数按"时:分:秒"格式化了，所以"学习数据"页把你的 39 小时显示成了 39 分钟。课程页是前端自己按分钟重算的，显示 39 小时 09 分。

## 一个需要你知道的数据残留

我为了摸清服务端校验边界，故意发过错误的 `class_id` 和 `period_type`。这两个字段平台不校验，直接新建了重复记录，于是：

- 总学习时长从 36 小时 21 分变成 39 小时 09 分，多算了 168 分钟（2 小时 48 分）
- 课程页"整体进度"显示 109.07%（课程列表仍然显示 100%，必修 16/16、选修 32/32 的完成状态也正常）
- 学习记录一共 52 行，但课时只有 48 个。多出来的都在两个课时上："AIGC的法律风险防控（更新）"有 4 行（其中 2 行 `class_id` 是 999999，被平台自己标成不属于当前班级），多算 147 分钟；"应用的组成：后端与数据库（豆包工作）"有 2 行（班级字段正常，只是 `period_type` 不同），多算 21 分钟

平台没有删除或重置进度的接口（试了 11 个候选接口名全是 404），要彻底清掉这几条重复记录得让班主任在后台删。不影响刷课和取证，脚本统计"已学/要求"时按每节要求时长封顶，这两个数字仍然是真实的 36 小时 21 分。
